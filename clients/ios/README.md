# ScheduleKit iPhone 小组件（Scriptable）

在 iPhone **桌面**和**锁屏**上看任务概览。不需要 Mac、不需要 Xcode、
不需要开发者账号 —— 用 [Scriptable](https://scriptable.app)（免费 App）。

```
服务端 GET /api/tasks ×2 + GET /api/ingest   （只读密钥）
        ↑ HTTPS
ScheduleKitWidget.js（Scriptable 里的 JS）
        ↓ Script.setWidget()
iOS 桌面 / 锁屏小组件
```

## 先明确一件事：小组件是**只读**的

iOS 的交互式小组件需要 App Intents，Scriptable 不提供 —— 它的渲染 API 里
根本没有按钮类型（官方文档 ListWidget 一节可以核对）。所以**不能**在小部件里
直接勾选完成。点击只能跳转。

本项目里各客户端的定位：

| 客户端 | 能做什么 |
|---|---|
| Windows 悬浮窗 | 显示 + **勾选完成**（读写密钥） |
| iPhone 小组件 | **只能看**，点开跳 WebUI 去勾（只读密钥） |
| iPhone 快捷指令 | 拍照/说话录入 → 草稿箱 |

## 一个反直觉的好消息：倒计时是实时的

任务列表要靠 iOS 决定何时刷新（实测 15–60 分钟一次，平台限制，Scriptable
没有强制刷新 API）。但 `WidgetDate` 渲染出来的时间是 **iOS 自己维护的**，
会自己走。

所以「还剩 3 天 4 小时」这种倒计时**永远是准的**，只有列表内容可能滞后。
刚录入完的任务不会立刻出现 —— 那时在 Scriptable 里跑一次脚本预览即可。

## 安装

### ① 服务端建一个只读密钥

`/settings` → API 密钥 → 名称填「iPhone 小组件」→ **勾上「只读」** → 创建。
明文只显示一次，复制下来。

> 只读密钥读不了 `/api/settings` 和 `/api/keys`，改不了配置，也写不了任务。
> 泄露的影响面仅限于"别人能看到你的待办"。

### ② 装 Scriptable

App Store 搜索 **Scriptable**（作者 Simon Støvring，免费）。

### ③ 新建脚本并粘贴

打开 Scriptable → 右上角 `+` → 把 `ScheduleKitWidget.js` 全文粘进去。

### ④ 填 CONFIG

只改最上面那一段：

```js
const CONFIG = {
  BASE_URL: "https://canisa1ph.duckdns.org:8443",   // 一般不用改
  API_KEY: "sk_在这里粘贴只读密钥",                    // ← 换成你的密钥
  ...
};
```

### ⑤ 先在 App 里跑一次（**别跳过这步**）

点脚本右下角的 ▶ 运行。会弹出**自检报告**：

```
✓ BASE_URL：https://canisa1ph.duckdns.org:8443
✓ API_KEY：已填写（sk_xxxx…）
✓ /healthz 可达 · 版本 0.1.0 · Asia/Shanghai
✓ 鉴权通过 · 有序表 2 条
✓ 无序表 0 条
✓ 草稿箱 · 待确认 0 条
✓ 缓存可读写
✓ 六种尺寸渲染均通过
```

**任何一项是 ✗，先解决它再加小组件。** 小组件出错时屏幕上只有一块空白，
看不出原因；自检会把原因直接打出来。

报告下面有三个按钮：**预览中号** / **预览锁屏** / 关闭 —— 可以先看看效果。

> 如果这一步**什么都没弹**，别往下走，先看「排障」第一节。

### ⑥ 加到桌面

长按桌面 → 左上角 `+` → 搜 **Scriptable** → 选**中号** → 添加 →
长按小组件 → 编辑小组件 → Script 选 `ScheduleKitWidget`。

### ⑦ 加到锁屏（可选）

长按锁屏 → 自定 → 锁定屏幕 → 添加小组件 → Scriptable → 选矩形尺寸 →
再进编辑选同一个脚本。脚本会按 `config.widgetFamily` 自动换成锁屏排版。

## 显示什么

**中号（桌面）**

```
ScheduleKit                      ● 2 条待确认
09-21 23:59  第一周作业：习题一        6 天后
11-06 22:00  完成课程论文并提交        1 个月
Ⅱ  背单词（每天 30 个）
Ⅳ  整理实验室器材清单
```

- 上半部分：**有序表**（有截止时间）前 2 条，按时间升序
- 下半部分：**无序表**（无截止时间）前 2 条，按 Ⅰ→Ⅴ
- 右上角：待确认草稿数，**点它直接进草稿箱**；待确认为 0 时整块隐藏
- 点其他地方：打开 WebUI 任务列表

**锁屏矩形**

```
第一周作业：习题一
6 天后 · 09-21 23:59
```

只放最近的一条 —— 锁屏空间小，而这恰好是最高价值的信息。

脚本还处理了 `small` / `large` / `accessoryCircular` / `accessoryInline`，
所以以后加别的尺寸也不会崩。

## 可调项

都在脚本顶部的 `CONFIG` 里：

| 键 | 默认 | 说明 |
|---|---|---|
| `ORDERED_LIMIT` | 2 | 中号显示几条有序表 |
| `UNORDERED_LIMIT` | 2 | 显示几条无序表 |
| `TIMEOUT_SECONDS` | 4 | **别调大到 10 以上**，见下 |
| `REFRESH_MINUTES` | 15 | 只是请求 iOS 的**下限提示**，不是保证 |
| `TIMEZONE` | `Asia/Shanghai` | 与服务端 `[server].timezone` 一致 |

**为什么超时只有 4 秒**：iOS 给小组件构建时间线的预算很紧（原生 WidgetKit
约 5 秒）。卡满默认的 60 秒，小组件会被系统掐死 —— 连缓存的兜底都来不及渲染。
实测从国内到这台 VPS，三个并行请求约 1.2–1.7 秒，4 秒很宽裕。

## 出错时会看到什么

刻意让每种失败都有**明确的话**，而不是一块空白：

| 情况 | 小组件显示 |
|---|---|
| 密钥无效/被吊销 | `密钥无效或已吊销 —— 去服务端 /settings 重新创建一个只读密钥` |
| 连不上服务器 | `连不上服务器：…` |
| 服务器 5xx | `服务器返回 HTTP 502` |
| 断网，但之前成功过 | 上次的任务 + `⚠ 离线 · 上次更新：42 分钟前` |
| 真的没有待办 | `没有待办 🎉` |

**注意**：`没有待办` 和 `密钥无效` 是两件事。开发时实测抓到过一个 bug ——
401 时草稿箱那个请求恰好返回 200，于是小组件显示成了「没有待办 🎉」，
用户会以为自己真的没事可做。现在鉴权错误一律优先判定，有回归用例钉住。

## 排障

### 桌面上「啥都没有」—— 按这个顺序查

这是最常见的现象，而且最坑：**小组件里脚本一抛异常，iOS 就只是不渲染** ——
不报错、不超时、服务器也收不到任何请求，屏幕上就是一片空白。
所以别猜，按下面三步走。

#### 第 0 步：先跑 `diagnose.js`

在 Scriptable 里**新建一个脚本**（不要覆盖主脚本），把 `diagnose.js` 粘进去，
点 ▶ 运行。它会连问三关：

| 关卡 | 过了说明 | 没过说明 |
|---|---|---|
| ① 能弹出对话框 | Scriptable 本身正常 | App 层面的问题，重装 Scriptable |
| ② `/healthz` 通 | 手机网络 + 证书没问题 | 网络问题；用手机浏览器打开 `…:8443/healthz` 对照 |
| ③ 只读密钥能读任务 | 数据链路完全没问题 | 密钥错/被吊销，去 `/settings` 重建 |

**三关都过 → 问题在渲染或小组件配置，往下走。**

#### 第 1 步：在 App 里跑主脚本（不是点小组件）

打开主脚本，点 ▶。**正常应当弹出一份「自检报告」。**

- **弹出报告** → 脚本没问题，是小组件配置的事，看第 2 步
- **弹出「脚本出错」** → 照着里面的报错信息改
- **什么都没弹** → 见下面「连对话框都不弹」

#### 第 2 步：检查小组件配置

1. 长按小组件 → **编辑小组件** → `Script` 是否选中了 `ScheduleKitWidget`
   （没选的话显示的是占位内容）
2. 小组件尺寸是否匹配 —— 脚本六种尺寸都处理了，但锁屏只能放
   `accessoryRectangular` 这一种
3. 删掉小组件重新添加一次，iOS 会立刻重跑脚本

#### 第 3 步：脚本是不是存在 iCloud 里且没下载到本机

Scriptable 有一个已知问题：**脚本放在 iCloud Drive 且未下载到本机时，
小组件会静默地什么都不显示**（[论坛原帖](https://talk.automators.fm/t/my-scripts-take-a-long-time-to-load-and-widgets-do-nothing/18292)）。

判断方法：打开「文件」App → iCloud Drive → Scriptable，看脚本文件是否有
云朵图标（表示未下载）。**点一下让它下载**，再重跑小组件。

**更稳的做法**：把脚本放在 **「我的 iPhone」本地**而不是 iCloud。
Scriptable 的设置里可以改脚本目录。

### 连对话框都不弹

说明脚本根本没跑起来，最可能是**语法错误**（比如粘贴时被截断）。
检查：

1. 脚本是不是完整 —— 最后一行应当是 `}`，文件末尾不该有半截内容
2. 粘贴时用的编辑器是否把全角/半角引号改掉了
3. 重新从仓库复制一次全文（`clients/ios/ScheduleKitWidget.js`）

### 小组件显示「脚本出错：…」

这是**好事** —— 说明兜底生效了。把冒号后面的信息发出来即可定位。

以前这里会是一片空白：小组件里抛异常时 iOS 只是不渲染。

### 小组件空白 / 不更新

iOS 决定刷新时机，可能几十分钟不动。删掉重新添加会立刻重跑一次。

**刚录入的任务不会立刻出现** —— 这是平台限制，不是 bug。
急用时在 Scriptable 里跑一次脚本预览即可。

### `密钥无效或已吊销`

去 `/settings` 重新创建一个只读密钥，更新脚本里的 `API_KEY`。

### 中文或罗马数字显示成方块

不太可能（用的是系统字体），但如果出现，检查脚本是不是被编辑器改过编码 ——
粘进 Scriptable 时应当是 UTF-8。

## 在电脑上预览（开发用）

不用 iPhone 也能跑同一份脚本：

```bash
# 用 fixture 渲染，不需要服务端
node clients/ios/preview.mjs --fixtures <目录> --family medium

# 直接打真实服务器（密钥走环境变量，不要写进脚本）
SK_API_KEY=sk_xxx node clients/ios/preview.mjs --live
```

它会用 stub 顶掉 Scriptable 的 API，把渲染结果打成终端文本。
`tests/test_ios_widget.py` 的端到端用例走的就是这条路：用进程内应用生成
**真实**的接口响应当 fixture，再跑脚本断言输出。

## 关于密钥存放

密钥明文写在脚本顶部的 `CONFIG` 里。这是权衡后的选择：

- 脚本文件本身就在 Scriptable 的沙盒里，与放进 Keychain 是**同一层保护**
  （Scriptable 的 Keychain 不是 iCloud 钥匙串，只在 App 内部）
- 而"小组件进程里能不能读到 Keychain"没有实机验证过
- 少一个不确定性，就少一种"桌面上莫名空白"的可能

**介意的话**：Scriptable 若开了 iCloud 同步，脚本（含密钥）会同步到 iCloud。
只读密钥风险有限；要更保守就关掉同步，或改用 Keychain 并接受上面那个不确定性。

不再用了就去 `/settings` 吊销那把密钥 —— 小组件下一个刷新周期就会显示
「密钥无效」，不会静默失败。
