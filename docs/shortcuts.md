# Apple 快捷指令搭建指南

目标：**拍照 → 上传 → 确认 → 入库**，全程在手机上完成。

快捷指令由你自己搭（你更清楚自己的使用习惯），这份指南给出每个动作的确切配置、
常见坑，以及上线前的验证清单。

> 动作名称以中文 iOS 为准，不同 iOS 版本措辞可能略有差异——按描述找对应动作即可。

---

## 0 · 先创建一个 API Key（1 分钟，只做一次）

服务端打开 **`/settings` → 「API 密钥」**：

- 名称填「快捷指令」
- **不要勾「只读」**（确认草稿时要写数据库）
- 点「创建」，**立刻复制那串 `sk_...`** —— 它只显示这一次，服务端只存 SHA-256，之后取不回

## 1 · 最短可用版：5 个动作

新建快捷指令，依次添加：

### 动作 1 · 拍照
> 「拍照」/ Take Photo

或用「选择照片」从相册挑。两者返回的都是图像，后续动作通用。

### 动作 2 · 转换图像 ← **不能省**
> 「转换图像」/ Convert Image

| 参数 | 值 |
|---|---|
| 格式 | **JPEG** |
| 质量 | 0.8 |

**为什么必须转**：iPhone 拍照默认是 **HEIC**，服务端不支持（Pillow 原生解不了它）。
不转的话会收到 415。质量 0.8 足够识别，上传也快得多。

### 动作 3 · Base64 编码
> 「Base64 编码」/ Base64 Encode

输入 = 上一步的图像。**展开动作选项，把「换行符」关掉。**

**为什么要关**：开启时会在结果里插入换行，服务端解码失败返回 422。

### 动作 4 · 获取 URL 内容 ← 核心
> 「获取 URL 内容」/ Get Contents of URL

先展开「显示更多」，然后：

| 字段 | 值 |
|---|---|
| **URL** | `https://你的域名:8443/api/ingest` |
| **方法** | `POST` |
| **请求体** | `JSON` |
| **头部** | 见下 |

**请求体的三个键**（点「添加新字段」，类型都选**文本**）：

| 键 | 值 |
|---|---|
| `channel` | `image`（直接手打，不是变量） |
| `image_base64` | 点值区域 → 插入变量 → **Base64 编码**的结果 |
| `mime` | `image/jpeg` |

**头部一个键**：

| 键 | 值 |
|---|---|
| `Authorization` | `Bearer sk_你复制的密钥` |

> 建议把密钥先放进一个「文本」动作放在最开头，头部里引用它。以后轮换密钥时
> 只需要改那一处。

### 动作 5 · 打开确认页
> 「打开 URL」/ Open URLs

URL 的值：先加一个 **「从输入获取词典值」**（Get Dictionary Value），
键填 `confirm_url`，输入设为**动作 4 的结果**；然后把这个结果作为「打开 URL」的输入。

跑起来就是：拍一张 → 等几秒 → 自动打开网页确认页，逐条核对后点「确认入库」。

## 2 · 加上「确认」分支（推荐）

上面那版每次都要在网页上手点一下。想更快就再加一个动作：

### 动作 5' · 直接确认

> 「获取 URL 内容」

| 字段 | 值 |
|---|---|
| URL | 把动作 4 的返回先经「从输入获取词典值」取出 `confirm_url`，再拼上 `/confirm` |
| 方法 | `POST` |
| 头部 | 同动作 4 |
| 请求体 | **留空**（表示"就用识别结果"） |

> 拼 URL 更省事的做法：不要用 `confirm_url`，而是先用「从输入获取词典值」取
> `draft_id`，然后拼 `https://你的域名:8443/api/ingest/{draft_id}/confirm`。

### 更稳的做法：菜单二选一

加一个 **「从菜单中选取」**，三个选项：

| 选项 | 后续动作 |
|---|---|
| 直接入库 | `POST .../{draft_id}/confirm`，请求体留空 |
| 先核对 | 「打开 URL」→ `confirm_url` |
| 丢弃 | `POST .../{draft_id}/discard` |

识别不确定时（比如截图里有多个事项、字迹潦草）走「先核对」，省的比确认那一下多得多。

## 3 · 从分享菜单直接触发（强烈推荐）

比"打开快捷指令再拍照"顺手得多：**相册里选中截图 → 分享 → 你的快捷指令**。

在快捷指令的详情页（点右上角 ⋯ → 详情）：

1. 打开 **「在共享表单中显示」**
2. 「接受」的类型勾上 **图像**、**媒体**
3. 「如果无输入则」→ **询问**（这样直接运行时会让你选图）

然后把动作 1 从「拍照」改成 **「快捷指令输入」**（Shortcut Input），其余不动。

这样微信/相册里的截图可以直接分享过来识别，比重新拍照清晰得多。

## 4 · 文本版：一句话记下来

不拍照时，记一句话更快。复制一份快捷指令，把动作 1–3 换成一个「文本」动作：

- 动作 1：**「文本」**（或「要求输入」/ Ask for Input）
- 动作 2：「获取 URL 内容」

| 字段 | 值 |
|---|---|
| URL | `https://你的域名:8443/api/ingest` |
| 方法 | `POST` |
| 请求体 | JSON |
| `channel` | `text` |
| `text` | 引用上一步的文本 |

服务端会把**时间与课表上下文**一起交给模型，所以「下节课交第三章习题」这类
指代能被解析成具体日期——前提是课表已录入且 `[term].start_date` 设对了。

**再加个彩蛋**：用「听写文本」（Dictate Text）替代「要求输入」，
就是对 Siri 说一句话自动记下来。

## 5 · 服务端返回什么

```json
{
  "draft_id": 12,
  "status": "pending",
  "channel": "image",
  "items": [
    {
      "title": "第三章习题 3.1-3.5",
      "category": "homework",
      "due_at": "2026-03-27T15:59:00+00:00",
      "priority": null,
      "notes": "交到学委处",
      "source_quote": "下周五前交到学委处",
      "needs_priority": false,
      "adjustments": []
    }
  ],
  "context_snapshot": "[当前时间] 2026-03-20 星期五 14:32（第 3 周）\n[正在进行] 高等数学 …",
  "image_url": "/api/ingest/12/image",
  "confirm_url": "https://你的域名:8443/drafts/12",
  "llm_elapsed_ms": 2810
}
```

字段含义：

| 字段 | 说明 |
|---|---|
| `items[].category` | `homework` 作业 / `practice` 练习 / `exam` 考试 / `appointment` 要约 / `other` 其他 |
| `items[].due_at` | UTC ISO8601；**为 `null` 表示无截止时间**，此时 `priority` 有值 |
| `items[].priority` | 1=Ⅰ … 5=Ⅴ；**仅在 `due_at` 为 null 时出现**（二选一） |
| `items[].source_quote` | 图上支撑这条判定的原文，方便你核对 |
| `items[].needs_priority` | `true` = 模型既没给时间也没给优先级，服务端默认填了 Ⅲ，**重点核对这条** |
| `confirm_url` | 直接打开就能核对的网页 |

**关键：这一步还没有创建任何任务。** 必须再调确认接口才入库。

**如果 `items` 是空数组**：没识别到任何事项。此时打开确认页会显示 0 条，
应该点「丢弃」——确认接口对空草稿会返回 422。

## 6 · 六个坑

### ① 忘了「转换图像」→ 415

```
415  收到的是 HEIC/HEIF 图片，服务端不支持该格式。
     请在客户端先转成 JPEG：快捷指令里加一个「转换图像」动作，格式选 JPEG，再上传。
```

服务端把怎么修写在错误信息里了，照做即可。

### ② Base64 的「换行符」没关 → 422

`image_base64 不是合法 base64`。回到动作 3 展开选项关掉它。

### ③ 图片太大 → 413

上限是服务端 `[llm].max_image_bytes`（默认 8MB，可在 `/settings` 调）。
在「转换图像」里把质量调到 0.6–0.8 通常就够。

### ④ 识别失败 → 502，**不是你的错**

```json
{ "detail": { "message": "识别失败：…", "draft_id": 13, "retryable": true } }
```

表示 LLM 调用失败（超时、没按要求调用工具、密钥失效等）。**草稿已留档**
（含模型原始返回），所以重新上传一次即可；要查原因看服务端日志。

### ⑤ 未配置 LLM → 503

去 `/settings` 填 Base URL / 模型 / API Key，保存后**立即生效不用重启**。
注意模型必须同时支持**图片输入**与**强制 tool_choice**。

### ⑥ 401 / 403

- `401` 密钥错或已被吊销 → 去 `/settings` 重新创建
- `403 该密钥为只读` → 创建时勾了「只读」，重新建一个读写密钥

**排障用 trace id**：每个响应都带 `X-Trace-Id` 头。在服务端：

```bash
journalctl -u schedulekit | grep 't=你看到的traceid'
```

就能拉出那一次请求的完整链路（含 LLM 耗时、后处理改了什么）。

## 7 · 上线前验证清单

按顺序各跑一遍，每步都有明确预期：

| # | 操作 | 预期 |
|---|---|---|
| 1 | 拍一张**有明确截止时间**的通知 | 识别出的条目 `due_at` 有值，`priority` 为 `null` |
| 2 | 拍一张**没有任何时间**的便签 | `due_at` 为 `null`，`priority` 是 1–5 |
| 3 | 发一句「下节课交作业」 | 解析出的日期 = 该课的下一次上课日（前提：课表已录入、`[term]` 已设对） |
| 4 | 故意跳过「转换图像」直接传原图 | 收到 415，且提示里写着「转换图像」 |
| 5 | 确认入库后打开首页 | 有序表/无序表各就各位 |
| 6 | 从相册分享一张截图 | 能触发快捷指令（如果做了第 3 节） |

第 3 条最容易出问题，也最能体现这套系统值不值：

- 课表在 **`/courses`** 录入
- 学期起始日在服务端 `/etc/schedulekit/config.toml` 的 `[term].start_date`，
  **改完要重启服务**（`sudo systemctl restart schedulekit`）
- 判断标准：打开 `/courses`，顶部显示的周次对不对——显示「非学期周」就说明起始日不对

## 8 · 把 WebUI 加到主屏幕

Safari 打开服务端地址 → 分享 → **添加到主屏幕**。

这样确认页、任务列表都有一键入口。8443 端口上的 HTTPS 同样是安全上下文，
Service Worker 会正常注册（但**只在 HTTPS 下工作**）。
