# Apple 快捷指令接入指南

目标：**拍照 → 上传 → 确认 → 入库**，全程在手机上完成。

快捷指令由你自己搭（这部分你更清楚自己的使用习惯），这里提供接口规格、
逐步说明，以及几个容易踩的坑。

---

## 一、准备

1. 服务端打开 `/settings` → 「API 密钥」→ 创建一个名为「快捷指令」的密钥
   - 权限选**读写**（确认草稿时要写数据库）
   - **明文只显示一次**，先复制到备忘录
2. 记录服务端地址，例如 `https://schedulekit.duckdns.org:8443`

---

## 二、最短可用流程（5 个动作）

| # | 快捷指令动作 | 配置 |
|---|---|---|
| 1 | **拍照** | 或用「选择照片」 |
| 2 | **转换图像** | 格式 **JPEG**，质量 0.8 ← **必需**，见下方坑① |
| 3 | **Base64 编码** | 输入为上一步结果，**关闭**「换行符」 |
| 4 | **获取 URL 内容** | 见下表 |
| 5 | **显示结果** / **打开 URL** | 用返回值里的 `confirm_url` |

第 4 步的配置：

- **URL**：`https://你的域名:8443/api/ingest`
- **方法**：`POST`
- **请求体**：`JSON`
  - `channel`（文本）：`image`
  - `image_base64`（文本）：上一步的 Base64 结果
  - `mime`（文本）：`image/jpeg`
- **头部**：
  - `Authorization`：`Bearer 你的APIKey`
  - `Content-Type`：`application/json`

> 建议把 API Key 放在「文本」动作里再用变量引用，方便日后轮换。

## 三、返回值长什么样

```json
{
  "draft_id": 12,
  "status": "pending",
  "items": [
    {
      "title": "第三章习题 3.1-3.5",
      "category": "homework",
      "due_at": "2026-03-27T15:59:00+00:00",
      "priority": null,
      "notes": "交到学委处",
      "source_quote": "下周五前交到学委处",
      "needs_priority": false
    }
  ],
  "context_snapshot": "[当前时间] 2026-03-20 星期五 14:32（第 3 周）\n[正在进行] 高等数学 · 教三201 …",
  "image_url": "/api/ingest/12/image",
  "confirm_url": "https://你的域名:8443/drafts/12",
  "llm_elapsed_ms": 2810
}
```

**关键点：这一步还没有创建任何任务。** 必须再调确认接口才入库。

## 四、两种确认方式，按你的偏好选

### 方式 A：立刻确认（最省事）

再接一个「获取 URL 内容」：

- URL：`https://你的域名:8443/api/ingest/⟨draft_id⟩/confirm`
- 方法：`POST`
- 头部同上传
- 请求体：**留空**（表示"就用识别结果"）

适合：信任识别结果、只想快速记下来。

### 方式 B：跳到网页核对（推荐，尤其识别不确定时）

取出 `confirm_url`，用「打开 URL」动作打开它。

网页上可以逐条改标题/分类/时间或优先级、删掉误识别的条目，再点「确认入库」。
**在快捷指令里编辑嵌套 JSON 非常难用**，所以这条路其实更顺手。

### 方式 C：混合

上传后弹「菜单」让你选：确认 / 去核对 / 丢弃。三条路分别对应
`confirm` / `confirm_url` / `discard`。

## 五、只想记一句话？用文本通道

不拍照时可以直接发文本：

- URL：`https://你的域名:8443/api/ingest`
- 请求体（JSON）：`channel` = `text`，`text` = 你的内容（如「下节课交第三章习题」）

服务端会把**时间上下文**（现在几点、第几周、正在上/刚结束/即将开始哪门课）
一起交给模型，所以「下节课」「这门课」这类指代能被解析成具体日期。

## 六、四个必须知道的坑

### ① 必须先把照片转成 JPEG

iPhone 拍照默认是 **HEIC**，服务端不支持（Pillow 原生解不了它）。
不转换的话会收到：

```
415  收到的是 HEIC/HEIF 图片，服务端不支持该格式。
     请在客户端先转成 JPEG：快捷指令里加一个「转换图像」动作，格式选 JPEG，再上传。
```

「转换图像」动作放在 **Base64 编码之前**。

### ② Base64 编码要关掉「换行符」

开启时会在结果里插入换行，服务端解码会失败并返回 422。
在这个动作的展开选项里把「换行符」关掉。

### ③ 图片别太大

上限是服务端 `[llm].max_image_bytes`（默认 8MB，可在 `/settings` 调）。
超了会收到 413。在「转换图像」里把质量调到 0.6–0.8 一般就够，
而且上传更快、识别质量基本无差别。

### ④ 识别失败时会返回 502，不是你的错

```json
{
  "detail": {
    "message": "识别失败：…",
    "draft_id": 13,
    "retryable": true
  }
}
```

含义是 LLM 调用失败（超时、没按要求调用工具、密钥失效等）。
**草稿已经留档**（含模型原始返回），所以：

- 想重试：再上传一次即可
- 想查原因：`journalctl -u schedulekit | grep "t="`，或看 `/settings` 里的状态

## 七、验证清单

搭完之后按顺序验一遍：

1. 拍一张包含明确截止时间的通知 → 应识别出带 `due_at` 的条目，且 `priority` 为 `null`
2. 拍一张没有任何时间的便签 → 应识别出 `priority`（1–5），`due_at` 为 `null`
3. 拍一张课表截图 → 保存到 `/courses`，再发「下节课交作业」，检查解析出的日期是不是那门课的下一次课
4. 故意上传一张 HEIC（跳过转换）→ 应收到 415 且提示里写着「转换图像」
5. 确认入库后打开 `/` → 有序表/无序表各就各位

---

## 八、把 WebUI 添加到主屏幕

Safari 打开服务端地址 → 分享 → **添加到主屏幕**。

8443 端口上的 HTTPS 同样是安全上下文，所以 Service Worker 会正常注册；
但注意 **Service Worker 只在 HTTPS 下工作**，用 `http://` 访问时不会有离线外壳
（数据本来也需要联网，影响很小）。
